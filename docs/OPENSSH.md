# OpenSSH 终端模式

连接列表中的 OpenSSH 开关只影响本页面随后打开的 SSH 终端，不修改已保存的连接。开启后，后端通过真实伪终端启动系统 OpenSSH；主机密钥确认、密码和验证码均直接在终端中输入。密码是否回显由 OpenSSH 控制，前端不会预测回显。

此模式用于直连、密码认证的兼容性排查。保留原有 SSH2 模式；代理、跳板、私钥连接暂不支持 OpenSSH 模式。已保存密码不会传给系统命令，需重新在终端输入。

## 使用

1. 管理员确认是否允许不录像的终端会话。启用会话录像时，OpenSSH 模式会拒绝启动；不要为了排障擅自绕过组织录像要求。
2. 打开连接列表的 OpenSSH 开关，选择已保存的直连 SSH 连接。
3. 对照服务器提供的主机密钥指纹完成确认，再按提示输入密码或验证码。每次会话使用独立的主机信任文件，因此需要重新确认指纹。
4. 输入指纹确认、密码或验证码期间，标签状态点为蓝色。OpenSSH 确认身份验证成功后，状态点变绿。关闭连接后，状态点变红。

此模式不支持现有 SFTP 文件管理、监控和会话挂起，也不记录终端录像。关闭终端会结束本次 OpenSSH 进程。输入不放入命令行参数、环境变量或应用日志。

## 部署与维护

后端和整合 Docker 镜像安装 `openssh-client`。本机或桌面部署需要系统已安装 OpenSSH 客户端：Windows 使用系统目录下的 `System32/OpenSSH/ssh.exe`，Linux/macOS 使用 `/usr/bin/ssh`。使用的是**后端所在机器**的网络和 OpenSSH，不是访问网页的电脑。

后端新增固定版本 `node-pty` 1.1.0，提供 Linux/macOS PTY 和 Windows ConPTY。Node 的普通子进程管道不提供完整终端语义，因此不能替代它。该原生依赖增加平台二进制和构建工具需求；沿用 npm 锁文件和桌面运行时依赖收集机制，不新增框架。Linux 源码构建需要 Python、make、C++ 工具链，Docker 构建已有这些工具。各平台安装包仍须分别验证原生模块加载。

OpenSSH 参数不读取用户 SSH 配置，不继承 SSH agent，禁用转发和 SSH 转义命令。认证完成后，客户端执行应用固定的本地命令，在本次会话目录创建空文件，用来通知标签更新状态。当前模式使用隔离的临时 known_hosts，退出后清理。原 SSH2 模式继续处理需要应用级 SSH 通道的高级功能。

本地测试通过不等于特定目标服务器已恢复；应在实际部署环境中验证目标地址、账号、主机指纹及多轮认证。

Windows 下释放已退出的 ConPTY 时，node-pty 的控制台辅助进程可能输出 `AttachConsole failed`。本地测试确认调用公开清理接口后进程能够自然退出；此提示不表示远程认证失败。
